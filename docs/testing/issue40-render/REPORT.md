# Issue 40 candidate B: sparse authored-facade visibility synchronization

Status: **rejected for performance selection**. The implementation is isolated on `codex/issue-40-render` for review, with no merge. It preserves the measured content and collision, but two matched warm repeats yield a preregistered score of **0.99605** (a 0.395% weighted regression). The course p95 differences are within run variation and one candidate Hills run has a late 89.716 ms frame. The 16.7 ms target remains open.

## Scope and rationale

The Metropolis authored facade kit also runs in the Hills city slice. It caps additive detail at 28 active faces, 6,000 mesh entities and 1.5 million triangles. Before this change, `synchronize` visited every authored mesh each render frame to find its owning face, although settled groups have camera-independent visibility and range. Issue 25's release diagnostics identified CPU frame costs much larger than measured GPU pass times. This candidate targets CPU render-world bookkeeping, not shader quality or scene density.

Each group already owns its primitive entity IDs. It now stores its last synchronized weight and visits those entities only during a fade or the frame that settles it. Active fades still update camera-relative dither margins every frame. New groups start unsynchronized. The unused `AuthoredMesh.face` field becomes a marker component. Source mesh handles, materials, face selection, fade duration, distance ranges, triangle/resident limits, building collision, and physical actors are unchanged. No dependencies or external media were imported.

## Content and visual parity

After excluding recorded timing fields, both Hills `hills-revision.json` surveys match their baseline counterparts exactly across bridge, city, clouds, scenery, collision, traffic and recovery data. Both Metro runs match exactly across farm placements, streets, pedestrians, crossings, survey counts, and the authored-facade kit's 14 views after excluding load-to-material-ready seconds. No primitive cap, triangle cap, physical envelope, source layout hash, or static collider count changed. An untimed Metro capture produced 14 views. Against the issue 40 GPU agent’s visual baseline capture (whose exact launched binary path/hash was not recorded), views 02–13 have mean absolute RGB channel difference at most 0.0161 on a 0–255 scale; three are exactly pixel-equal. Views 00/01 have different startup camera orientations and are not pose-matched evidence. [Per-view measurements](visual-comparison.json) and the [paired Metro facade image](images/metro-05-baseline.png) / [candidate image](images/metro-05-candidate.png) are retained. An untimed full Hills survey exited zero with all 17 expected screenshots; visual inspection of [city](images/hills-city-candidate.png), [farm](images/hills-farm-candidate.png) and [canyon](images/hills-canyon-candidate.png) shows resident scenery and no obvious facade holes. No frozen-baseline Hills screenshot pair is available, so Hills pixel parity remains unverified; matching structural surveys remain the stronger content check.

## Verification and decision

Formatting, strict Clippy (`cargo clippy --workspace --locked --all-targets -- -D warnings`), locked release build, source provenance audit (580 dependency declarations / 198 runtime asset records / 28 research observations), and `sync_progress.py --check` pass. `cargo test --workspace --locked` passes 617 tests with two ignored and zero failed; the test groups are 433, 1, 57 and 126 passes. The native two-course survey cases all exit zero. No task is marked complete: PERF-08, RFU-PERF-02 and P16-003 retain full-race, target-hardware, GPU attribution, and 16.7 ms gates. This experiment is retained as a reviewable draft PR and should not be selected for integration on the current evidence. Reconsider only after a stronger independent repeated win on the integrated content baseline, with the tail spike and visual parity resolved.
