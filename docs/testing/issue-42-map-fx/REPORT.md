# Issue #42 map atmosphere — staged implementation

Branch: `codex/issue-42-map-fx`; source baseline `e2a31918`, plus scope commit `36246757` (cherry-picked as `aef7c9b6`). Engine remains pinned to Bevy 0.17.3. No external repository, image, shader, sound, or proprietary media was copied. The alpha textures and motion are generated in `src/map_fx.rs`.

RFU-FX-04 is the new stable Part 15 requirement for Valley coverage under issue #42. Its reason, dependency, acceptance and verification are in README and the synced progress index. The wildlife-integrated checklist is 228 verified / 321 open; no RFU-FX gate is closed.

## Scope and bounds

| Map | Cue | Default capacity | Visibility |
| --- | --- | ---: | --- |
| Hills western town/desert | Rising translucent heat bands | 16 | 115 m, off road |
| Hills town/desert | Feathered wind-blown dust billows | 48 | 125 m, roadside |
| Metropolis and legacy city | Slow vent steam | 16 | 100 m, off road |
| Valley | Quiet air motes | 16 | 90 m, off road |

`ROADDASH_MAP_FX=0` allocates none, `low` uses half the counts, and the default uses the table above. Every preset distributes stations over the intended map span. One 64×64 soft texture and, on Hills, separate original 64×64 heat-band and dust textures are generated. A single quad mesh and one immutable material per cue kind are shared. The animation scales soft sprite envelopes and never mutates material assets during PostUpdate. Placement is deterministic from route station and index. All entities are created during world setup, and presentation animation runs in PostUpdate after the camera, before transform propagation. The phase derives from fixed-loop race time, so zero-tick render frames and frame-rate changes do not advance it; pause freezes motion and retry resets it. No collider, drivetrain, Sand surface, save schema, camera postprocess, or fixed simulation path is edited.

The user rejected the thin sand stream after native review. The current design uses an original 64×64 feathered, asymmetric dust mask on the fixed pool of gray-brown translucent billboards. Each plume expands, lifts and travels along the shoulder with a smooth life envelope. Origins sit about 1–2 m off the pavement edge; the visual gust may drift a few metres over the road at low opacity without a collider or surface-physics change. Anchors call the same barycentric ground-height function that seats rendered Hills terrain, then add a positive lift. The same 48 sprites are evenly spaced across the western approach and desert; the low preset spans the same distance with 24. The final centered rider-height chase pair showed a visible see-through billow. For API guidance only, we reviewed Bevy's pinned [v0.17.3 transparency example](https://github.com/bevyengine/bevy/blob/v0.17.3/examples/3d/transparency_3d.rs) and [v0.17.3 textured-quad example](https://github.com/bevyengine/bevy/blob/v0.17.3/examples/3d/texture.rs). They establish `AlphaMode::Blend`/unlit textured material behavior; no source code or media was copied.

The heat bands are a translucent rising air cue, not screen-space refraction or a custom shader. They need native visual review for whether they convincingly read as heat shimmer. Their low alpha avoids obvious foreground distortion, but that also may make them too subtle. Steam is the first city effect because a wet road would require matching model-derived distant proxy materials under MAT-03. Existing depth fog is the option for later city depth grading after baseline visual review. The transparent StandardMaterial pipeline is reused; first-use shader compilation stalls have not yet been measured.

The opt-in `--map-fx-survey` takes paired small/large phase views at the same Hills heat and sand anchors, normal chase-height views in the western town and desert, plus a paired view on each other map. Run it with `ROADDASH_MAP_FX=0` and the default for native before/after; per-run JSON records pool counts and bounded paused-view and active-simulation wall frames. These views are not a full-race or GPU timing certificate.
